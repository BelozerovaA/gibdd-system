# Запуск в Docker

Вся система поднимается одной командой: база данных, сервис ГИБДД, сервис камер и сайт. Мобильное приложение в Docker не запускается (это приложение для телефона), оно подключается к уже запущенному сервису ГИБДД.

## Что запускается

| Сервис | Что это | Адрес снаружи |
|---|---|---|
| `web` | Сайт: готовая сборка React, раздаёт nginx. Он же перенаправляет запросы `/api` и `/ws` в backend | http://localhost:3000 |
| `backend` | Сервис ГИБДД: API и WebSocket. Документация API | http://localhost:8000/docs |
| `camera-service` | Сервис камер | http://localhost:9000/health (только с вашего компьютера) |
| `db` | MySQL 8.4 | снаружи недоступен |

Файл [docker-compose.yml](../docker-compose.yml) описывает, как они связаны. Все четыре сервиса видят друг друга по именам внутри сети Docker (`backend`, `camera-service`, `db`).

## Что нужно установить

**Docker Desktop** (на Windows он использует WSL2; установщик сам подскажет включить нужные компоненты). Проверка:

```powershell
docker --version
docker compose version
```

Команды в этой инструкции написаны через `docker compose` (с пробелом, это современная версия).

## Первый запуск

Все команды выполняются в **корне репозитория** (там, где лежит `docker-compose.yml`).

**1. Создайте файл настроек `.env`** и поменяйте значения:

```powershell
copy .env.example .env
```

Откройте `.env` и задайте три значения:

| Переменная | Что вписать |
|---|---|
| `MYSQL_ROOT_PASSWORD` | Пароль базы данных. Только буквы и цифры: символы `@ : / # %` ломают адрес подключения |
| `SECRET_KEY` | Длинная случайная строка. Сгенерировать: `python -c "import secrets; print(secrets.token_hex(32))"` |
| `SERVICE_TOKEN` | Общий секрет сервиса ГИБДД и сервиса камер. Латиница и цифры. Сгенерировать: `python -c "import secrets; print(secrets.token_hex(16))"` |

Для демонстрации удобно поставить:

- `CAMERA_INTERVAL_SECONDS=10`: камеры будут «видеть» автомобиль каждые 10 секунд;
- `FOUND_PROMPT_DELAY_MS=10000`: вопрос «задержан?» появится через 10 секунд, а не через минуту;
- `ALERT_COOLDOWN_SECONDS=20`: после ответа новое оповещение по той же машине возможно через 20 секунд, а не через две минуты.

Оповещений при этом не будет больше одного за раз: пока сотрудник не ответил, повторные события камер игнорируются ([правила частоты](../backend/docs/camera-events.md#правила-частоты-и-зачем-они-нужны)).

**2. Создайте файл с тестовыми сотрудниками:**

```powershell
copy backend\seed_users.example.json backend\seed_users.json
```

Логины и пароли из него будут созданы в базе при первом старте. Файл не попадает в образ и в git.

**3. Соберите и запустите:**

```powershell
docker compose up --build
```

Первая сборка занимает несколько минут (скачиваются образы, ставятся зависимости). Потом запуск занимает около минуты: контейнеры стартуют по порядку, каждый дожидается здоровья предыдущего.

```
db  →  backend (ждёт базу, заполняет её, запускает сервер)  →  camera-service
                                                           →  web
```

**4. Откройте сайт** http://localhost:3000 и войдите логином и паролем из `backend\seed_users.json`.

Чтобы запустить в фоне, добавьте `-d`: `docker compose up --build -d`.

## Как проверить, что всё работает

```powershell
docker compose ps
```

У `db`, `backend`, `camera-service` и `web` в столбце STATUS должно быть `healthy` (или `Up`).

| Проверка | Адрес | Что должно быть |
|---|---|---|
| Сервис ГИБДД | http://localhost:8000/ | `{"message": "GIBDD API", "status": "running"}` |
| Документация API | http://localhost:8000/docs | страница Swagger |
| Сервис камер | http://localhost:9000/health | `{"status": "ok", "cameras": 15, "watchlist": …}` |
| Сайт | http://localhost:3000 | страница входа |

## Демонстрация оповещения

1. Войдите на сайте под тестовым сотрудником и откройте «Мой розыск».
2. Добавьте автомобиль в розыск. В течение нескольких секунд сервис ГИБДД отправит список камерам.
3. С интервалом `CAMERA_INTERVAL_SECONDS` камеры сами «увидят» автомобиль, и на сайте появится окно оповещения с картой.
4. Не хотите ждать: вызовите **ручную фиксацию** ([пример команды](../camera-service/README.md#ручная-фиксация)), оповещение придёт сразу.

Что делает каждая часть и как проверить обмен между сервисами: [camera-service/docs/testing.md](../camera-service/docs/testing.md).

## Повседневные команды

| Что нужно | Команда |
|---|---|
| Посмотреть журнал всех сервисов | `docker compose logs -f` |
| Журнал одного сервиса | `docker compose logs -f camera-service` |
| Остановить, сохранив данные | `docker compose stop` (запуск снова: `docker compose start`) |
| Остановить и удалить контейнеры, данные сохранить | `docker compose down` |
| **Удалить всё, включая базу данных** | `docker compose down -v` |
| Пересобрать после изменения кода | `docker compose up --build` |
| Пересобрать один сервис | `docker compose up --build -d backend` |
| Перезапустить один сервис | `docker compose restart camera-service` |
| Тесты backend внутри контейнера | `docker compose run --rm --no-deps --entrypoint python backend -m unittest discover -s tests` |

Тесты сервиса камер в образ не копируются, запускаются у вас локально: `python -m unittest discover -s tests` в папке `camera-service`.

## Подключение мобильного приложения

Сервис ГИБДД опубликован на порту 8000 вашего компьютера, к нему приложение подключается так же, как раньше:

| Откуда | Адрес сервера в приложении |
|---|---|
| Эмулятор Android | `10.0.2.2:8000` (по умолчанию) |
| Реальный телефон в той же Wi-Fi сети | `IP_компьютера:8000`, например `192.168.0.15:8000`. IP показывает `ipconfig` |

Адрес вводится на экране входа в «Настройках сервера». Если телефон не достаёт до компьютера, разрешите порт 8000 в брандмауэре Windows для частных сетей.

## Где хранятся данные

База данных лежит в томе Docker `gibdd_db_data`. Он переживает `docker compose down` и пересборку образов. Удаляется только командой `docker compose down -v`.

Файлы `seed_users.json` и `.env` не копируются в образы: первый монтируется в контейнер только на чтение, вторые читает сам `docker compose`.

## Если что-то не работает

| Что видите | Причина и решение |
|---|---|
| `required variable MYSQL_ROOT_PASSWORD is missing` (или `SECRET_KEY`, `SERVICE_TOKEN`) | Нет файла `.env` или в нём не задана переменная. Выполните шаг 1 |
| `bind source path does not exist: …seed_users.json` | Нет файла с тестовыми сотрудниками. Выполните шаг 2 |
| `port is already allocated` (порт 8000, 3000 или 9000) | Порт занят другой программой. В `docker-compose.yml` поменяйте левое число в `ports`, например `"8001:8000"` |
| `backend` перезапускается, в журнале `Access denied for user 'root'` | Вы поменяли `MYSQL_ROOT_PASSWORD` после первого запуска: база помнит старый пароль. Верните старый или удалите данные: `docker compose down -v` |
| `backend` пишет `База данных не отвечает` | Подождите: MySQL при первом старте инициализируется до минуты. Если не проходит, смотрите `docker compose logs db` |
| `Не найден файл с тестовыми сотрудниками` в журнале backend | Файл есть, но в нём ошибка, либо путь неверный. Сообщение подскажет, что исправить |
| `exec ./docker-entrypoint.sh: no such file or directory` | В скрипте Windows-переводы строк. В образе они убираются автоматически; если ошибка осталась, выполните `docker compose build --no-cache backend` |
| Сайт открывается, но вход не проходит, в консоли браузера ошибка сети | Backend не готов: `docker compose ps`, `docker compose logs backend` |
| Оповещения не приходят | `http://localhost:9000/health` показывает `watchlist` больше нуля? Если 0, посмотрите `docker compose logs backend` (ищите «Не удалось отправить список розыска») и проверьте, что `SERVICE_TOKEN` один для всех (он задаётся одним значением в `.env`) |
| В журнале камер `сервис ГИБДД ответил 401` | Токены не совпадают. Это бывает, если `.env` поменяли, но контейнеры не пересоздали: `docker compose up -d` |
| В журнале камер `ответ ГИБДД {'status': 'ignored', 'reason': ...}` | Это нормально: правила частоты или автомобиль не в розыске. Значения причин: [protocol.md](../camera-service/docs/protocol.md#ответы-сервиса-гибдд) |

## Почему так устроено

- **nginx перед backend.** Сайт обращается к `/api` и `/ws` на своём же адресе, nginx перенаправляет их в backend. Поэтому не нужно настраивать CORS, а адрес API не зависит от компьютера, на котором всё запущено.
- **База не опубликована наружу.** Её порт не занят на вашем компьютере, значит, не будет конфликта с установленным MySQL. Снаружи она и не нужна: ходит в неё только backend.
- **`depends_on` с проверкой здоровья.** Контейнеры стартуют не просто «после», а «когда предыдущий готов», поэтому не бывает ошибок вида «сайт запустился раньше backend».
- **Тестовые сотрудники монтируются файлом.** Логины и пароли не попадают в образ, а значит, и в реестр образов.
- **Отдельные контейнеры для сервисов.** Это и есть смысл выноса камер: сервис камер можно остановить, пересобрать или заменить, не трогая остальных.
- **Контейнеры работают не от root.** У `backend` и `camera-service` свой непривилегированный пользователь.

## Для боевого использования

Docker-конфигурация рассчитана на учебный проект. Перед использованием в реальных условиях: смените все пароли и ключи, отключите ручную фиксацию (`ENABLE_MANUAL_DETECTIONS=false`), уберите публикацию порта 9000, поставьте перед системой HTTPS и хешируйте пароли сотрудников (см. [backend/docs/security.md](../backend/docs/security.md)).
