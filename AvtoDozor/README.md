# АвтоДозор: мобильное приложение (React Native)

Мобильный клиент системы оперативного розыска ГИБДД. Работает с тем же сервисом ГИБДД (backend на FastAPI + MySQL), что и веб-версия. О камерах приложение ничего не знает: оповещение для него это сообщение по WebSocket от сервиса ГИБДД, которое тот создаёт по событию от отдельного [сервиса камер](../camera-service/README.md). Веб-версия: сотрудник входит в систему, ведёт персональный список розыска, а когда камера «видит» разыскиваемый автомобиль, на телефон приходит оповещение, и карта сама открывается на сработавшей камере.

Приложение сделано по ТЗ «Мобильное приложение «АвтоДозор»»: React Native, HTTP/REST, WebSocket, авторизация по токену.

## Что умеет приложение (по ТЗ)

| Экран | Что делает | Рисунок в ТЗ |
|---|---|---|
| Вход | Логин и пароль, кнопка «Войти». До входа кнопок меню нет | 1 |
| Личный кабинет | ФИО, дата рождения, телефон, служебная почта, подразделение; кнопка «Выйти из системы» | 2 |
| Мой розыск | Персональный список в таблице (ГРЗ, статус, модель, цвет, время, дата, адрес); «Добавить в розыск» и «Удалить из розыска» | 3, 4 |
| База розыска | Все разыскиваемые автомобили всех сотрудников, **только просмотр** | 5 |
| Карта | Карта камер, кнопки «Увеличить +» и «Уменьшить −»; при тревоге сама переключается на сработавшую камеру | 6 |
| Оповещение | Окно с ГРЗ, местом, временем и датой; кнопка «Принять» | 7 |
| Результат розыска | Через интервал после «Принять» вопрос «Автомобиль задержан?»: «Да» исключает автомобиль из розыска, «Нет» оставляет | 8 |
| История оповещений | Таблица за выбранный период, «Обновить», «Экспорт» в Word или Excel | 9, 10 |

Внизу экрана находится меню из пяти кнопок, кнопка открытой страницы выделена цветом.

Дополнительно:
- Если на оповещение не ответили, приложение напоминает о нём повторно (раз в минуту и при возврате в приложение).
- Сессия сохраняется: после перезапуска входить заново не нужно, пока токен действителен (по умолчанию 30 минут).
- Если сервер вернул «токен истёк», приложение само выходит на экран входа.
- Таблицы тянутся вниз для обновления и прокручиваются вбок.

## Что нужно установить

| Что | Версия | Зачем |
|---|---|---|
| Node.js | 22.11 или новее | Сборка JavaScript, Metro |
| Android Studio | актуальная | Android SDK, эмулятор, Gradle |
| JDK | 17 или 21 | Идёт вместе с Android Studio (JetBrains Runtime), отдельно ставить не нужно |
| Docker Desktop | актуальная | Запускает сервер и сервис камер, к которым подключается приложение ([инструкция](../docs/docker.md)). Либо Python 3.12 и MySQL, если запускать без Docker |

**Настройка Android Studio (один раз)**
1. Откройте **Android Studio → More Actions → SDK Manager**. Во вкладке *SDK Platforms* отметьте последнюю платформу (проект использует API 37), во вкладке *SDK Tools* отметьте *Android SDK Build-Tools*, *NDK (Side by side)*, *Android SDK Platform-Tools*. Если чего-то не хватит, при первой сборке Android Studio сама предложит доустановить недостающее, соглашайтесь.
2. Задайте переменную окружения `ANDROID_HOME` (Windows): `C:\Users\ВАШЕ_ИМЯ\AppData\Local\Android\Sdk`, и добавьте в `PATH` папку `%ANDROID_HOME%\platform-tools`. После этого перезапустите терминал.
3. Создайте эмулятор: **Device Manager → Create Device** (например, Pixel с последним образом Android).

## Запуск (эмулятор)

**1. Запустите сервер** (в корне репозитория). Проще всего через Docker, он поднимет базу данных, сервис ГИБДД, сервис камер и сайт:

```powershell
copy .env.example .env                                  # впишите пароль БД, SECRET_KEY, SERVICE_TOKEN
copy backend\seed_users.example.json backend\seed_users.json
docker compose up --build
```

Подробная инструкция и решение проблем: [docs/docker.md](../docs/docker.md). Сервис ГИБДД будет доступен на порту 8000 вашего компьютера, к нему и подключается приложение.

Для быстрой демонстрации в `.env` поставьте `CAMERA_INTERVAL_SECONDS=10` и `ALERT_COOLDOWN_SECONDS=20`: камеры будут «видеть» автомобиль каждые 10 секунд. Оповещение можно вызвать и вручную, не дожидаясь камер: [пример команды](../camera-service/README.md#ручная-фиксация).

Без Docker backend и сервис камер запускаются по отдельности: [backend](../backend/README.md#быстрый-старт-без-docker) и [сервис камер](../camera-service/README.md#запуск).

**2. Установите зависимости приложения** (один раз, в папке `AvtoDozor`):

```powershell
npm install
```

**3. Запустите эмулятор** из Device Manager и дождитесь, пока загрузится Android.

**4. Запустите приложение** в папке `AvtoDozor`:

```powershell
npm run android -- --active-arch-only
```

Эта команда соберёт приложение, установит его в эмулятор и сама запустит Metro. **Первая сборка идёт долго (10-20 минут):** Gradle скачивает зависимости, это нормально. Следующие запуски занимают секунды. Флаг `--active-arch-only` собирает приложение только под архитектуру эмулятора и заметно ускоряет сборку.

Если Metro нужно запустить отдельно: `npm start` в одном окне и `npm run android` в другом.

**5. Войдите.** Тестовые сотрудники создаются при первом запуске сервера (в Docker это делает сам контейнер, без Docker команда `python seed.py`). Логины и пароли лежат в `backend/seed_users.json`, вот шаблон:

| Логин | Пароль |
|---|---|
| `ivanov_ai` | `Ivanov2024` |
| `petrova_ea` | `Petrova2024` |
| `belozerov_rv` | `Admin2024` |

Эмулятор видит компьютер по адресу `10.0.2.2`, поэтому в приложении ничего настраивать не нужно.

## Запуск на реальном телефоне

1. На телефоне включите **режим разработчика** (Настройки → О телефоне → несколько раз нажмите «Номер сборки») и **отладку по USB**. Подключите телефон кабелем к компьютеру и разрешите отладку.
2. Проверьте, что телефон виден: `adb devices` (в списке должно быть устройство `device`).
3. Телефон и компьютер должны быть **в одной Wi-Fi сети**. Узнайте IP компьютера: `ipconfig`, строка «IPv4-адрес», например `192.168.0.15`.
4. Сервер должен быть доступен с телефона: Docker публикует порт 8000 на всех адресах компьютера, а без Docker backend запускают с `--host 0.0.0.0`. При первом запуске Windows спросит про брандмауэр, разрешите доступ в частной сети (для Docker Desktop или Python).
5. Запустите `npm run android -- --active-arch-only`.
6. На экране входа нажмите **«Настройки сервера»**, впишите `192.168.0.15:8000` (ваш IP) и нажмите «Сохранить адрес». Затем войдите.

Адрес сервера запоминается, пересобирать приложение для его смены не нужно.

## Как получить установочный файл APK

Чтобы передать приложение преподавателю или поставить на телефон без компьютера:

```powershell
cd android
.\gradlew.bat assembleRelease
```

Готовый файл: `android\app\build\outputs\apk\release\app-release.apk`. Скопируйте его на телефон и установите (разрешите установку из неизвестных источников). Этот APK подписан отладочным ключом: годится для защиты проекта, но не для публикации в магазине.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| «Нет связи с сервером» при входе | Убедитесь, что сервер запущен (`docker compose ps` показывает `healthy`, http://localhost:8000/ открывается в браузере). Эмулятор: адрес `10.0.2.2:8000`. Телефон: IP компьютера, одна Wi-Fi сеть, брандмауэр разрешает порт 8000 |
| Красный экран «Unable to load script» | Не запущен Metro (`npm start`) или телефон его не видит: выполните `adb reverse tcp:8081 tcp:8081` и перезапустите приложение |
| `SDK location not found` | Создайте файл `android\local.properties` со строкой `sdk.dir=C\:\\Users\\ВАШЕ_ИМЯ\\AppData\\Local\\Android\\Sdk` |
| Gradle просит другую версию JDK | Android Studio → Settings → Build Tools → Gradle → Gradle JDK: выберите встроенный JDK (JetBrains Runtime 17 или 21) |
| `adb` не найден | Не задан `PATH` до `platform-tools` (см. настройку Android Studio) |
| Оповещения не приходят | У сотрудника должны быть автомобили в «Моём розыске»; камеры должны получить список (`http://localhost:9000/health` показывает `watchlist` больше нуля); пока вы не ответили на прошлое оповещение, новых нет, ответьте «Да» или «Нет»; вызовите ручную фиксацию и посмотрите ответ ([пример](../camera-service/README.md#ручная-фиксация)) |
| Сборка падает после смены версий | `cd android`, затем `.\gradlew.bat clean`, и повторите `npm run android` |
| Экспорт не скачивается | Кнопка «Экспорт» открывает ссылку в браузере телефона, нужно разрешить скачивание. Ссылка живёт 2 минуты |

## Известные ограничения

- Оповещения приходят, пока приложение открыто (WebSocket). Push-уведомления при закрытом приложении (Firebase) в ТЗ не требуются и не реализованы: при срабатывании backend дополнительно отправляет письмо на служебную почту.
- Приложение подключается к серверу по `http://` (учебный проект в локальной сети). Для реальной эксплуатации нужен HTTPS, и тогда в манифесте нужно убрать `usesCleartextTraffic`.
- Токен действует 30 минут (настройка `ACCESS_TOKEN_EXPIRE_MINUTES` на сервере), после этого нужно войти снова.
