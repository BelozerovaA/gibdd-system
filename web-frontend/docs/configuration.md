# Настройка и сборка

## Переменные окружения

Файл `web-frontend/.env` (шаблон: [`.env.example`](../.env.example)) в git не попадает.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `REACT_APP_API_URL` | `http://localhost:8000/api` | Адрес API backend. Может быть относительным (`/api`): тогда сайт и API на одном адресе, как в Docker |
| `REACT_APP_WS_URL` | выводится из `REACT_APP_API_URL` | Адрес WebSocket (`ws://host:8000/ws`). Нужен, только если он не совпадает с адресом API |
| `REACT_APP_FOUND_PROMPT_DELAY_MS` | `60000` | Пауза между «Принято» и вопросом «Автомобиль задержан?» |

Как выводится адрес WebSocket:

- адрес API абсолютный: схема `http` заменяется на `ws`, окончание `/api` отбрасывается, добавляется `/ws`. Например, `http://192.168.0.15:8000/api` даёт `ws://192.168.0.15:8000/ws`;
- адрес API относительный (`/api`): берётся адрес самой страницы. На `http://localhost:3000` получится `ws://localhost:3000/ws`, на `https://…` защищённый `wss://…/ws`.

Create React App читает переменные **только при запуске** (`npm start`) и при сборке. После изменения `.env` перезапустите сервер разработки. Имена должны начинаться с `REACT_APP_`.

Разбор значений находится в [`src/config.js`](../src/config.js).

## Запуск и сборка

```powershell
npm install          # зависимости, один раз
npm start            # запуск для разработки на http://localhost:3000
npm run build        # сборка для публикации в папку build/
```

Собранную папку `build/` можно отдать любым статическим веб-сервером. Адрес API при этом **зашивается в сборку** на момент `npm run build`, поэтому `REACT_APP_API_URL` задают до сборки.

## В Docker

В [`Dockerfile`](../Dockerfile) приложение собирается с `REACT_APP_API_URL=/api`, а готовые файлы раздаёт nginx. Его [`nginx.conf`](../nginx.conf) делает три вещи:

- запросы `/api/…` перенаправляет в backend (`http://backend:8000`);
- запросы `/ws/…` перенаправляет туда же с заголовками `Upgrade`, чтобы заработал WebSocket, и с долгим таймаутом;
- любой другой адрес (например, `/dashboard` после обновления страницы) отдаёт `index.html`, дальше маршрутизацию ведёт React Router.

Благодаря этому не нужен CORS, а адрес API не зависит от компьютера, на котором всё запущено. Значение `FOUND_PROMPT_DELAY_MS` из корневого `.env` передаётся при сборке образа, поэтому после его изменения образ нужно пересобрать: `docker compose up --build`.

## Связь с backend

- Backend по умолчанию принимает запросы с любых адресов (CORS открыт), поэтому адрес сайта настраивать на сервере не нужно.
- Если backend запущен на другом компьютере или порту, измените `REACT_APP_API_URL` и перезапустите.
