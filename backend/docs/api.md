# REST API и WebSocket

Базовый адрес: `http://localhost:8000`, все маршруты начинаются с `/api`.
Интерактивная документация, которую FastAPI строит сам и где запросы можно отправлять прямо из браузера: `http://localhost:8000/docs` (Swagger) и `/redoc`.

## Общие правила

- **Авторизация.** После входа сервер выдаёт JWT-токен. Его передают в заголовке `Authorization: Bearer <токен>`. Токен действует 30 минут (`ACCESS_TOKEN_EXPIRE_MINUTES`).
- **Формат.** Запросы и ответы в JSON, кроме выгрузки отчётов (`/alerts/export`) и WebSocket.
- **Ошибки.** Тело ответа `{"detail": "текст ошибки"}`. Коды: `400` нарушено правило (например, «Автомобиль уже в розыске»), `401` токен недействителен или истёк, `404` запись не найдена, `422` тело запроса неверного формата.
- **Свои данные.** Сотрудник видит и меняет только свои оповещения. Чужое оповещение даёт `404`.

Два маршрута (`available-plates` и `violation-categories`) открыты без токена: они отдают только справочные значения.

## Авторизация

### `POST /api/auth/login`

Тело:

```json
{ "login": "ivanov_ai", "password": "..." }
```

Ответ `200`:

```json
{
  "access_token": "eyJhbGciOi...",
  "token_type": "bearer",
  "user_id": 2,
  "full_name": "Иванов Алексей Игоревич",
  "position": "Инспектор ДПС",
  "email": "ivanov@gibdd-kirov.example"
}
```

Ошибка `401`: `Неверный логин или пароль` (также для отключённого сотрудника, `is_active = false`).

## Сотрудники

### `GET /api/employees/me`

Профиль текущего сотрудника:

```json
{
  "id": 2, "login": "ivanov_ai", "full_name": "Иванов Алексей Игоревич",
  "birth_date": "14.03.1990", "phone": "+7 900 000-00-00",
  "email": "ivanov@gibdd-kirov.example", "position": "Инспектор ДПС",
  "hire_date": "01.09.2019",
  "department_name": "Управление ГИБДД по Кировской области", "is_active": true
}
```

`GET /api/employees` возвращает список таких объектов.

## Розыск

Объект записи розыска (`WantedVehicleResponse`) одинаков для `/my` и `/all`:

```json
{
  "id": 1, "plate": "А111АА43", "model": "Lada Vesta", "color": "Белый",
  "status": "В розыске",
  "fix_time": "12:00:00", "fix_date": "03.10.2026", "fix_address": "ул. Московская 106/1",
  "employee_name": "Иванов Алексей Игоревич",
  "reaction_status": "Ожидает", "found_status": "Нет"
}
```

Если данных нет, поля `fix_*` содержат `-`.

| Маршрут | Что делает |
|---|---|
| `GET /wanted/my` | Активные записи текущего сотрудника (в том числе со статусом `Найден`) |
| `GET /wanted/all` | Активные записи всех сотрудников |

### `POST /api/wanted/add`

Тело: `{ "plate": "А111АА43", "reason": "Угон" }`. Ответ: `{ "message": "...", "id": 12 }`.

Правила: автомобиль должен быть в справочнике `vehicles` (иначе `404 Автомобиль не найден`) и не должен иметь активной записи розыска у любого сотрудника (иначе `400 Автомобиль уже в розыске`). Причина ищется в `violation_categories` по названию; если такой нет, создаётся новая категория с кодом `CUSTOM`.

### `POST /api/wanted/take/{wanted_id}`

Передаёт розыск текущему сотруднику. Запись прежнего сотрудника закрывается (`is_active = false`, статус `Передан`), для текущего создаётся новая со статусом `В розыске`, а данные последней фиксации (`fix_*`) копируются. Ответ: `{ "message": "...", "id": 15 }`.

Ошибки: `404 Запись не найдена`; `400 Это уже ваш розыск`; `400 Автомобиль уже не находится в розыске` (если статус записи не `В розыске`, например `Найден`).

### `DELETE /api/wanted/{plate}`

Снимает с розыска автомобиль по ГРЗ: активная запись **текущего** сотрудника получает `is_active = false` и статус `Удален`. Чужую запись удалить нельзя (`404 Запись не найдена`). Если ГРЗ нет в справочнике: `404 Автомобиль не найден`.

### Справочники

- `GET /wanted/available-plates` возвращает список строк: ГРЗ автомобилей, у которых нет активной записи розыска.
- `GET /wanted/violation-categories` возвращает список названий причин. Если справочник пуст, отдаёт `["Угон", "Попытка угона", "Нарушение ПДД"]`.

## Оповещения

Объект истории (`AlertResponse`):

```json
{
  "id": 5, "vehicle_plate": "А111АА43",
  "alert_date": "03.10.2026", "alert_time": "12:00:00",
  "address": "ул. Московская 106/1", "camera_id": 8,
  "reaction_status": "Принято", "found_status": "Нет",
  "wanted_status": "В розыске", "is_viewed": true
}
```

### `GET /api/alerts/history`

Параметр `period` (необязательный): `today`, `week` (7 дней) или `month` (30 дней). Без него возвращаются все оповещения. Результат: только оповещения текущего сотрудника, от новых к старым, не больше 200 записей.

### `GET /api/alerts/pending`

Оповещения, на которые сотрудник ещё не отреагировал (`reaction_status = Ожидает`, `found_status = Нет`), не больше 10, от новых к старым:

```json
[ { "id": 31, "plate": "В222ВВ43", "address": "ул. Ленина 1", "date": "03.10.2026", "time": "09:00:00" } ]
```

Клиенты используют это, чтобы повторно напомнить о неотвеченном оповещении.

### `PUT /api/alerts/{alert_id}/reaction`

Тело: `{ "reaction_status": "Принято" }` или `"Отклонено"`. Меняет реакцию в оповещении и в записи розыска, отмечает оповещение просмотренным. Ответ: `{ "message": "Статус обновлен" }`. Сервер не проверяет, что значение именно из этих двух: ответственность за корректные значения на клиенте.

### `PUT /api/alerts/{alert_id}/found`

Тело: `{ "found_status": "Да" }` или `"Нет"`.

| Значение | Что меняется в записи розыска |
|---|---|
| `Да` | статус `Найден`, реакция `Принято`; камеры получают список розыска без этого автомобиля, оповещений по нему больше нет |
| `Нет` | статус `В розыске`, реакция `Ожидает`; поиск продолжается |

Ответ: `{ "message": "Статус найден обновлен" }`.

### Экспорт истории в Word и Excel

Браузер или мобильный браузер не умеют передавать заголовок `Authorization` в обычной ссылке, поэтому скачивание идёт в два шага:

1. `POST /api/alerts/export-token` (с обычным токеном) возвращает `{ "token": "...", "expires_in": 120 }`. Это отдельный токен на 2 минуты, он годится **только** для скачивания отчёта.
2. `GET /api/alerts/export?format=docx&period=week&token=<токен из шага 1>`. Параметры: `format` обязателен (`docx` или `xlsx`), `period` необязателен (`today`, `week`, `month`). В ответ приходит файл `alerts_history.docx` или `alerts_history.xlsx`.

Ошибки `401`: `Ссылка на скачивание устарела, повторите экспорт`, `Недопустимый токен`, `Сотрудник не найден`.

## Камеры

`GET /api/cameras` возвращает список, `GET /api/cameras/{camera_id}` одну камеру (по числовому `id`, при отсутствии `404 Камера не найдена`):

```json
{ "id": 8, "camera_id": "CAM-08", "address": "ул. Московская 106/1",
  "latitude": 58.599, "longitude": 49.6547, "camera_type": "Мобильная",
  "speed_limit": 60, "is_active": true }
```

## События от сервиса камер

Этот маршрут вызывает не пользователь, а [сервис камер](../../camera-service/README.md). Вместо токена входа он требует заголовок `X-Service-Token` с общим секретом `SERVICE_TOKEN`. Полное описание протокола: [camera-service/docs/protocol.md](../../camera-service/docs/protocol.md), как сервис ГИБДД обрабатывает событие: [camera-events.md](camera-events.md).

### `POST /api/camera-events`

Тело:

```json
{
  "event_id": "9f3c1c7e8a5d4b6f9a2e0d1c3b4a5f67",
  "plate": "А123ВК43",
  "camera_code": "CAM-08",
  "detected_at": "2026-10-12T09:00:00+00:00"
}
```

| Поле | Ограничения |
|---|---|
| `event_id` | строка, 1–64 символа, уникальный номер события (повторная отправка того же события не создаёт второго оповещения) |
| `plate` | строка, 1–20 символов |
| `camera_code` | строка, 1–20 символов, код камеры из таблицы `cameras` |
| `detected_at` | дата и время ISO 8601, желательно с часовым поясом (без пояса считается UTC) |

Ответ `200` при создании оповещения: `{ "status": "accepted", "alert_id": 77, "delivered": true }`. Поле `delivered` показывает, дошло ли оповещение до сотрудника по WebSocket.

Ответ `200`, когда оповещение не нужно: `{ "status": "ignored", "reason": "..." }`, где `reason` это `not_wanted` (автомобиль не в розыске), `pending_alert` (на предыдущее оповещение не ответили), `cooldown` (прошло слишком мало времени) или `duplicate` (событие уже обработано).

| Код | Когда |
|---|---|
| `401` | Нет заголовка `X-Service-Token` или он неверный |
| `422` | Неизвестная или отключённая камера, либо поля неверного формата |
| `503` | На сервере не задан `SERVICE_TOKEN` |

## WebSocket: оповещения в реальном времени

Адрес: `ws://localhost:8000/ws/{employee_id}?token=<JWT>`.

- Токен должен принадлежать сотруднику с этим `employee_id`. Иначе соединение закрывается с кодом `4401` до подключения.
- На одного сотрудника одно соединение: новое заменяет старое.
- Клиент может присылать любые текстовые сообщения. Веб-клиент отправляет `ping` каждые 25 секунд, чтобы соединение не закрывалось из-за простоя.
- Сервер присылает сообщение, когда сервис камер сообщил о разыскиваемом автомобиле и создано оповещение:

```json
{
  "type": "detection",
  "alert_id": 77, "wanted_id": 1, "plate": "А111АА43",
  "camera_id": 8, "camera_number": 8,
  "address": "ул. Московская 106/1", "latitude": 58.599, "longitude": 49.6547,
  "date": "03.10.2026", "time": "12:00:00"
}
```

Если в момент оповещения у сотрудника нет открытого соединения, сообщение не пропадает: запись остаётся в базе с `notification_sent = false`, а клиент получит её позже через `GET /alerts/pending`.

`camera_number` это номер камеры на карте (1-15), по нему клиент выбирает картинку `cam_N`. `camera_id` это числовой идентификатор камеры в базе.
