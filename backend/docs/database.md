# База данных

Модели описаны в [`backend/app/models.py`](../app/models.py) (SQLAlchemy). СУБД: MySQL. Таблицы создаются автоматически при первом запуске сервера (`Base.metadata.create_all`) и командой `python seed.py`.

Эта страница сгенерирована по `models.py`: список таблиц и полей совпадает с кодом.

## Связи

| Родитель | Дочерняя таблица | Поле | Смысл | Обязательна |
|---|---|---|---|---|
| `departments` | `employees` | `department_id` | сотрудник работает в подразделении | нет |
| `vehicles` | `wanted_vehicles` | `vehicle_id` | автомобиль разыскивается | да |
| `employees` | `wanted_vehicles` | `employee_id` | сотрудник ведёт розыск | да |
| `violation_categories` | `wanted_vehicles` | `violation_category_id` | причина розыска | нет |
| `wanted_vehicles` | `alerts` | `wanted_id` | розыск порождает оповещения | да |
| `cameras` | `alerts` | `camera_id` | камера зафиксировала автомобиль | нет |
| `employees` | `alerts` | `employee_id` | оповещение адресовано сотруднику | нет |
| `employees` | `user_logs` | `employee_id` | действия сотрудника | да |

Все связи «один ко многим»: одна запись родителя, много записей дочерней таблицы.

## Особенности, о которых стоит знать

- **Даты и время хранятся строками** (`дд.мм.гггг`, `чч:мм:сс`), а не типом `DATETIME`. Поэтому фильтр истории по периоду сравнивает не строки, а даты, разобранные из строк (см. `in_period` в [`routes/alerts.py`](../app/routes/alerts.py)): сравнение строк `05.09.2026` и `03.10.2026` дало бы неверный результат.
- **Одна активная запись розыска на автомобиль.** Остальные записи (`Передан`, `Удален`) остаются как история с `is_active = false`.
- **В `alerts` хранятся копии ГРЗ и адреса** (`vehicle_plate`, `address`): история показывает значения «как было» на момент оповещения. К автомобилю оповещение привязано через `wanted_id`, прямого внешнего ключа на `vehicles` у него нет.
- **`wanted_vehicles.fix_camera_id`** хранит номер камеры строкой, внешний ключ не объявлен (на ER-диаграмме показан пунктиром).
- **Не используются в коде:** таблица `user_logs` и поле `vehicles.is_stolen`.
- **Недоставленное оповещение не теряется.** Если у сотрудника в момент срабатывания не было открытой страницы, в `alerts` остаётся запись с `notification_sent = false` и реакцией `Ожидает`; она видна на главной странице и в списке `GET /alerts/pending`.
