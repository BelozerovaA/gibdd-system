# Тестирование сервиса камер

## Автотесты

```powershell
cd camera-service
python -m unittest discover -s tests -v
```

Нужен только Python, зависимостей нет. Тесты запускают настоящие HTTP-серверы на свободных портах, поэтому работают так же, как сервис в бою, и занимают около секунды.

| Файл | Что проверяет |
|---|---|
| `test_config_and_data.py` | Настройки (значения по умолчанию, неверные значения), файл камер (15 камер, ошибки в файле), список розыска (приведение к единому виду, замена целиком, работа из нескольких потоков) |
| `test_client_and_emitter.py` | Формат запроса к сервису ГИБДД, повторы при `5xx` с тем же `event_id`, отсутствие повторов при `4xx`, выбор только из списка розыска и только работающих камер, ручная фиксация |
| `test_server.py` | Все маршруты: токен (нет, неверный, не настроен), проверка входных данных, слишком большое тело, неверный JSON, ответы `404` и `405`, ошибки `422` и `502` ручной фиксации |
| `test_contract_with_backend.py` | Согласованность с сервисом ГИБДД: коды и адреса камер, поля события, адреса маршрутов, заголовок токена |
| `test_end_to_end_protocol.py` | Оба сервиса вместе: список розыска доходит до камер, камеры сообщают только о розыске, оповещение одно до ответа, снятие розыска учитывается |

Последний тест использует настоящий код с обеих сторон: сервер и эмиттер сервиса камер, отправитель списка и правила решений из backend. Вместо базы данных там заглушка.

Тест согласованности пропускается, если рядом нет папки `backend` (например, внутри Docker-образа, куда она не копируется).

## Ручная проверка

Нужны запущенные сервис ГИБДД и сервис камер ([docs/docker.md](../../docs/docker.md)).

1. **Камеры подключены:** `GET http://localhost:9000/health` показывает `"cameras": 15`.
2. **Список дошёл.** Войдите на сайте под тестовым сотрудником и добавьте автомобиль в розыск. Через несколько секунд:

   ```powershell
   Invoke-RestMethod -Uri http://localhost:9000/v1/watchlist -Headers @{ "X-Service-Token" = $token }
   ```

   В списке должен появиться ГРЗ.
3. **Оповещение.** Выполните ручную фиксацию этого ГРЗ ([README](../README.md#ручная-фиксация)). В ответе `"status": "accepted"`, на сайте открывается окно оповещения и карта с подсвеченной камерой.
4. **Правила частоты.** Повторите ручную фиксацию, не отвечая на оповещение: ответ `ignored / pending_alert`.
5. **Не в розыске.** Зафиксируйте любой другой ГРЗ: `ignored / not_wanted`.
6. **Снятие розыска.** Нажмите «Удалить из розыска», через несколько секунд список у камер уже без этого ГРЗ.
7. **Недоступность.** Остановите сервис камер (`docker compose stop camera-service`), измените розыск на сайте (всё работает), запустите камеры снова (`docker compose start camera-service`): в течение нескольких секунд они получат актуальный список.
